# Gridder UI Principles

## 1. Canvas First

キャンバスを常に主役にする。常設UIはコンパクトな上部バーだけに抑え、選択対象がないときは右インスペクターを表示しない。ページをカードの集合にせず、作業空間を一枚の連続した面として扱う。

## 2. Direct Manipulation

作成、選択、移動、伸縮は対象そのものを操作して行う。ツールモードはポリゴン作成のように不可避な一時操作だけに限定する。現在の操作可能性は、カーソル、ハンドル、輪郭、ライブプレビューで示し、説明文に依存しない。

## 3. Restrained Hierarchy

- 白とニュートラルグレーを基調にし、選択と主要操作に一つのアクセント色を使う。
- 境界線、余白、文字のウェイトで階層を作り、装飾的な影やグラデーションを使わない。
- コンパクトな操作面では見出しを小さく保つ。
- 角丸は最大8pxとし、カードを入れ子にしない。
- 数値、アイコン、ラベルが変化してもレイアウトが動かない寸法を確保する。

## 4. Controls

- Undo、Redo、削除、回転、共有にはLucideの標準アイコンを使う。
- 二値設定にはチェックボックスまたはスイッチを使う。
- 色には文字ボタンではなくスウォッチを使う。
- 少数の表示モードにはsegmented controlを使う。
- 数値には単位を隣接表示した入力またはstepperを使う。
- 不慣れなアイコンにはTooltipを付ける。
- 見た目はGridder固有にし、フォーカス管理、Dismiss、衝突回避はheadless primitiveへ委譲する。

## 5. Feedback

- hoverでは操作できる対象だけを強調する。
- pressでは1〜2px相当の控えめな視覚応答を返す。
- 選択枠とハンドルはズーム率にかかわらず操作しやすい画面上サイズを保つ。
- 保存成功のような完了通知は短いToastで示す。
- 破壊的操作はUndo可能にし、頻繁な確認ダイアログを避ける。

## 6. Motion

- パン、ズーム、ドラッグ、伸縮にはアニメーションを加えない。
- インスペクター、Popover、Tooltipの出入りだけに120〜180msの短いtransitionを使う。
- 出現はease-out、退出はより短いease-inとする。
- 同じTooltip群を続けて見る場合は待ち時間を短縮する。
- `prefers-reduced-motion`を尊重する。

## 7. Contextual Inspector

右インスペクターには、現在の選択に有効な操作だけを表示する。単一図形では名前、寸法、外観、配置を示し、複数選択またはグループでは共通操作だけを示す。無効な設定を大量に並べない。

## 8. Prototype Review

プロトタイプは静止画の美しさだけで評価しない。次を実際に操作して確認する。

- 空白から図形を作るまで迷わないか
- 移動と伸縮の境界をカーソルだけで理解できるか
- パンと図形作成が競合しないか
- ズーム後もハンドルとグリッドが安定しているか
- インスペクターの出入りが視線やキャンバスを不必要に動かさないか
- 1366x768と1440x900でUIが重ならないか
