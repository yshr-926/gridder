# デプロイ後確認チェックリスト

このドキュメントは、Gridder アプリケーションのデプロイ後に実行すべき確認項目をまとめたものです。
すべての項目をチェックしてからデプロイ完了としてください。

---

## 事前確認

デプロイを開始する前に以下を確認してください。

- [ ] GitHub Actions CI がすべてパスしている
- [ ] リリースノート（CHANGELOG.md）が更新されている
- [ ] 最新コードが main ブランチにマージされている
- [ ] デプロイ先サーバーに SSH でアクセスできる
- [ ] Docker と Docker Compose がインストールされている

---

## デプロイ実行

- [ ] リポジトリの最新コードが取得された（`git pull origin main`）
- [ ] `docker compose build` が正常に完了した
- [ ] `docker compose up -d` でコンテナが正常に起動した
- [ ] `docker compose ps` でコンテナが Running 状態である

**確認コマンド:**

```bash
docker compose ps
# 期待結果: STATUS が "Up" であること
```

---

## 基本動作確認

### ヘルスチェック

- [ ] ヘルスチェックエンドポイント（/health）が 200 を返す

```bash
curl -I http://localhost:8080/health
# 期待結果: HTTP/1.1 200 OK
```

### ページ表示

- [ ] トップページが正常に表示される（`http://[server-ip]:8080`）
- [ ] グリッドが正常に描画される
- [ ] ツールバーが表示されている
- [ ] プロパティパネルが表示されている

---

## 機能確認

### 描画機能

- [ ] 描画モード（鉛筆アイコン）でセルをクリックして塗りつぶせる
- [ ] ドラッグで連続して塗りつぶせる
- [ ] 色の変更ができる（色設定がある場合）

### 選択・移動機能

- [ ] 選択モード（矢印アイコン）でオブジェクトを選択できる
- [ ] 選択したオブジェクトをドラッグで移動できる
- [ ] 移動時にグリッドにスナップする
- [ ] オブジェクトの回転ができる（90度単位）
- [ ] オブジェクトの削除ができる
- [ ] オブジェクトの複製ができる

### 消しゴム機能

- [ ] 消しゴムモードで塗りつぶしたセルを消去できる
- [ ] ドラッグで連続して消去できる

### キャンバス操作

- [ ] ズームイン・ズームアウトが動作する
- [ ] パン（キャンバスの移動）が動作する
- [ ] スケール設定が変更できる

### キーボードショートカット

- [ ] ショートカットキーが機能する（設定されている場合）
  - 例: D=描画, V=選択, E=消しゴム など

---

## データ管理確認

### エクスポート

- [ ] JSON エクスポートが動作する（ファイルがダウンロードされる）
- [ ] PNG 画像エクスポートが動作する
- [ ] JPEG 画像エクスポートが動作する

### インポート

- [ ] JSON ファイルをインポートして作業を復元できる
- [ ] インポート後のオブジェクトが正しく表示される

### 自動保存

- [ ] LocalStorage への自動保存が動作する
- [ ] ページをリロードしても作業状態が復元される

---

## パフォーマンス確認

- [ ] 初期ロードが 3 秒以内に完了する
- [ ] 描画操作がスムーズである（体感でラグがない）
- [ ] 多数のオブジェクト（10個以上）があっても動作が重くならない
- [ ] 長時間操作してもメモリリークが発生しない

**確認方法:**

1. ブラウザの開発者ツール > Network タブでロード時間を確認
2. Performance タブでフレームレートを確認
3. Memory タブでメモリ使用量の推移を確認

---

## セキュリティ確認

### セキュリティヘッダー

以下のセキュリティヘッダーが正しく設定されていることを確認:

- [ ] `X-Frame-Options: SAMEORIGIN`
- [ ] `X-Content-Type-Options: nosniff`
- [ ] `X-XSS-Protection: 1; mode=block`
- [ ] `Content-Security-Policy` が設定されている
- [ ] `Referrer-Policy` が設定されている

**確認コマンド:**

```bash
curl -I http://localhost:8080/ 2>&1 | grep -E "(X-Frame|X-Content|X-XSS|Content-Security|Referrer)"
```

### HTTPS（本番環境のみ）

- [ ] HTTP から HTTPS へのリダイレクトが機能している
- [ ] SSL 証明書が有効である
- [ ] 証明書の有効期限が十分にある（30日以上）

## ログ確認

- [ ] コンテナログにエラーがない

```bash
docker compose logs --tail 100 | grep -i error
# 期待結果: 致命的なエラーがないこと
```

- [ ] Nginx のアクセスログが記録されている

```bash
docker compose exec gridder cat /var/log/nginx/access.log | tail -20
# 期待結果: アクセスログが記録されていること
```

- [ ] エラーログに異常がない

```bash
docker compose exec gridder cat /var/log/nginx/error.log | tail -20
# 期待結果: 重大なエラーがないこと
```

## 問題が発生した場合

チェック項目で問題が発生した場合は、以下のドキュメントを参照してください。

- [デプロイガイド - トラブルシューティング](./deployment-guide.md#トラブルシューティング)
- [環境変数の設定](./environment-variables.md)

緊急時のロールバック手順:

```bash
# 前のバージョンに戻す
cd gridder
git checkout <previous-commit-hash>
docker compose down
docker compose up -d --build
```
