# ADR 0003: 第一リリースでは Konva を継続利用する

- Status: Accepted
- Date: 2026-09-04

## Context

Gridder の第一リリースは、デスクトップ向けのグリッドベースのビジュアルスケッチツールを対象とする。想定規模は約 500 図形、50,000 セル相当であり、超大規模な描画性能よりも、矩形の作成・移動・伸縮、選択、ズーム、パンを直感的かつ安定して提供することを優先する。

既存フロントエンドには Konva / react-konva による入力処理、ドラッグ、変形、ヒットテスト、ズーム、画像出力の実装資産がある。一方、進行中だった PixiJS への移行コードはセル集合と Yjs を中心に設計されており、新しいポリゴン中心の文書モデルとは一致しない。

## Decision

第一リリースのレンダラーには Konva / react-konva を継続利用する。

- 描画単位を「1 セル 1 Konva ノード」から「1 図形 1 ポリゴン」に変更する。
- 文書モデルと編集コマンドはレンダラーから独立させる。
- Konva 固有のイベントや座標変換はレンダラーアダプター内に閉じ込める。
- PixiJS 移行は行わない。想定規模で計測上の問題が確認された場合にのみ再評価する。
- 進行中の PixiJS レンダラーは、再利用可能な Interface とテストを選別した後にリポジトリから削除する。

## Consequences

- 既存の入力・変形・出力機能を活用でき、第一リリースまでの変更量を抑えられる。
- ポリゴン単位の描画により、セル数に比例したノード増加を避けられる。
- レンダラー交換の可能性は、独立した文書モデルとアダプター境界によって保持する。
- 現行構成と責務境界は [ターゲットアーキテクチャ](../architecture/target-architecture.md) を正とする。

## Reconsider When

- 実機計測で目標規模の操作応答性を満たせない。
- Konva では実現困難な描画機能が必須要件になる。
- レンダラー変更の便益が移行コストを明確に上回る。
