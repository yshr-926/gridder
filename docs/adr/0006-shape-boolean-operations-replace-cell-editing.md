# ADR 0006: セル編集を廃止し、図形どうしの結合・くり抜きで自由形状を作る

- Status: Accepted
- Date: 2026-09-08
- Supersedes: [ADR-0001](0001-grid-snapped-polygons.md) の「セルの追加・削除は正方形との論理和・差として同じポリゴンへ反映する」の部分

## Context

issue #49 で実装したセル編集は、図形をダブルクリックして図形編集状態へ入り、セルをドラッグして領域を足し引きし、`Enter` で確定する操作だった。運用してみて二つの問題が明らかになった（issue #62）。

1. **設計上の欠陥**: セル編集は「選択図形」と「ポインタが触れたセル」の論理和を取るだけで、触れたセルが図形に接しているかを問わない。元の矩形から離れたセルを選ぶと図形が飛び地に分裂する。ADR-0001 は差演算による非連結化だけを想定しており、和演算で飛び地が生まれるのは仕様の穴だった。
2. **操作コストが製品定義に反する**: `CONTEXT.md` は Gridder を「空間的なアイデアを素早く形にする」ツールと定義する。L 字ひとつ作るのにセルを何十個もなぞる操作は「素早く」に反する。

一方で、矩形の作成・移動・伸縮はすでに素早い直接操作として成立している。自由形状を作る手段は、この矩形操作の延長として提供するのが自然である。

## Decision

- セル編集（図形編集状態、セルのドラッグによる追加・削除、`Alt + ドラッグ`、`Enter` / `Esc` の確定・取消）を廃止する。単独図形のダブルクリックは何もしない。ダブルクリックはグループへ入る用途（spec §7）だけに残す。
- 代わりに、複数選択した図形に対する **結合（union）** と **くり抜き（difference）** を提供する。どちらもインスペクターのボタンから実行し、それぞれ一つの Command として Undo で元の図形をすべて戻す。
- **結合**は選択図形の論理和を取り、最前面の図形の id・重なり順・名前・スタイルを引き継いだ一つの図形にする。他の図形は削除する。
- **結合の結果が非連結になる場合（重ならず辺でも接しない図形どうし）は操作を拒否する。** 結合は「一つの図形を作る」操作であり、離れた図形を複数のまま残して名前とスタイルだけ揃えても、何も起きていないように見えるうえに Undo 履歴を消費するだけである。離れた図形を一体として扱う手段はグループ化がすでに担う。角だけで接する図形も一つの単純ポリゴンにならないため、非連結として扱う。
- **くり抜き**は最前面の図形を型として、それ以外の選択図形から差を取る。型は結果に関わらず消える（Illustrator パスファインダーの「前面オブジェクトで型抜き」に準じる）。差の結果が非連結なら独立した複数の図形へ分割し（ADR-0001）、分割で生まれた図形は元の図形の名前・スタイル・グループ所属を引き継いで元の図形の直上に置く。空になった図形は削除する。
- 論理演算は引き続き `packages/editor-core/src/boolean/` の Adapter（`PolygonBooleanEngine`）を使う。Command は Adapter を注入されて `apply` で結果を導出し、`invert` は演算前の図形・重なり順・グループをそのまま復元する。
- 分割で生まれる図形の id は元の id から決定的に導出する（`<元の id>-2`, `-3`, ...、使用中なら飛ばす）。`DocumentHistory` の Redo は `apply` を再実行するため、乱数で id を採番すると Redo のたびに id が変わるが、この導出なら同じ文書には同じ結果を返す。
- キーボードショートカットは付けない。spec に定義がなく、インスペクターの「現在の選択に有効な操作だけを表示する」原則（ui-principles §7）で複数選択時にだけ現れるボタンが発見性を担う。

## Consequences

- L 字は「矩形を二つ並べて結合」、凹みや穴は「矩形を重ねてくり抜き」で作れる。どちらも矩形操作の延長で、セルを一つずつなぞる必要がない。
- 図形が飛び地に分裂する経路がなくなる。非連結になるのはくり抜きの結果だけで、その場合は必ず独立した図形へ分割される。
- `interactionController` から `editingShape` 状態と関連イベントが消え、モーダルな一時操作はポリゴン作成だけになる。`ShapeEditLayer` と `shapeEditPreviewStore` は不要になった。
- spec §3・§5・§6.3・§7・§11、`CONTEXT.md` の「図形」「セル」、ADR-0001 の該当部分をこの決定に合わせて改訂した。「セル」はグリッドの単位・頂点を揃える単位としての意味だけを持つ。
- 結合は非連結なら拒否するため、ユーザーは Toast で理由（重なるか辺で接する図形を選ぶこと）を知る。確認ダイアログは出さない（ui-principles §5）。

## Alternatives Considered

- **セル編集を残し、接続性の制約を加える**: 触れたセルが図形に接するときだけ和を取る。飛び地は防げるが、操作コストの問題は解決しない。
- **非連結な結合を複数図形のまま受け入れる**: ADR-0001 の「一つの図形は一つの連結領域」に沿うが、見た目上は何も起きず、Undo 履歴だけが増える。Illustrator の複合パスに相当する概念を Gridder は持たず、グループ化で代替できる。
- **結合で複合図形（複数の外周を持つ一つの図形）を導入する**: 選択・変形・寸法・書き出しの規則が分岐し、ADR-0001 が避けたかった分岐を再び持ち込む。
- **分割片の id を呼び出し側の乱数 generator で採番する**: 既存 Command の慣例（id は呼び出し側が渡す）に近いが、Redo の再適用で id が変わるか、Command が内部状態を持つことになる。決定的な導出のほうが純粋な値のままで済む。

## Reconsider When

- 離れた図形を一つの図形として扱う要求（例: 一括の名前・寸法表示）が、グループ化では足りないと分かったとき。
- 図形の一部だけを直接なぞって足し引きする操作が、頂点操作（issue #50 系）の拡張で改めて求められたとき。
