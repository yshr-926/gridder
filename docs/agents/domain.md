# Domain Docs

コードベースを調査する際に、エンジニアリングスキルがこのリポジトリのドメイン文書を参照する方法を定める。

## 調査前に参照する文書

- リポジトリルートの **`CONTEXT.md`**。
- **`docs/adr/`**。作業対象に関係する ADR を読む。

これらのファイルが存在しない場合は、指摘や事前の作成提案をせず、そのまま作業を続ける。用語や意思決定が実際に確定した時点で、`/domain-modeling` スキルが必要な文書を作成する。

## ファイル構成

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
├── apps/
└── packages/
```

## 用語集の語彙を使用する

出力でドメイン概念に名前を付ける場合は、`CONTEXT.md` で定義された用語を使用する。用語集で避けるよう明記された同義語へ置き換えない。

必要な概念が用語集にない場合は、その表現が適切か再検討するか、`/domain-modeling` で扱う不足事項として記録する。

## ADR との矛盾を明示する

出力が既存の ADR と矛盾する場合は、暗黙に上書きせず明示する。

> _ADR-0007 と矛盾するが、再検討する価値がある。理由は…_
