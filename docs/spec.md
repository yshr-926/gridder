# Gridder 第一リリース仕様

## 1. プロダクト

Gridder は、空間的なアイデアをグリッド上で素早く形にし、画像で共有するためのデスクトップ向けビジュアルスケッチツールである。ラフな構想と実寸を意識したレイアウトの中間を扱う。

汎用ホワイトボード、精密 CAD、画像編集ソフト、共同編集サービスは第一リリースの対象にしない。

## 2. 対象環境

- ログイン不要の Web アプリ
- 第一リリースの必須環境は Chromium 系デスクトップブラウザ
- Firefox と Safari は後続の対応対象
- モバイル、Electron、Tauri、バックエンドサービスは対象外

## 3. 基本ワークフロー

1. 空のグリッドから開始する。
2. 空白部分を左ドラッグして矩形を作る。
3. 図形を直接ドラッグして移動し、表示されたハンドルで変形する。
4. 必要に応じてポリゴン、図形の結合・くり抜き、名前、実寸スケールを使う。
5. 描画範囲を確認し、JSONへ保存するかPNG/JPEGとして共有する。

## 4. 空間と表示

- 作業空間は無限で、グリッドを常時表示する。
- ホイールでカーソル位置を中心に即時ズームする。
- 中ボタンドラッグまたは `Space + ドラッグ` でパンする。
- ズームやパンに補間アニメーションを入れない。
- 図形が存在するとき、その外接範囲から描画範囲を自動設定する。
- 描画範囲は後から辺・角をドラッグして手動調整できる。
- `内容に合わせる` 操作で描画範囲を再び図形の外接範囲へ合わせられる。

## 5. 図形モデル

- すべての図形は、グリッド頂点にスナップした閉じたポリゴンとして保持する。
- 矩形は4頂点のポリゴンである。
- ポリゴンは直線の斜辺、凹形状、穴を持てる。
- 図形同士の重なりを許可し、前後関係を保持する。
- くり抜きで図形が非連結になった場合、独立した複数の図形へ分割する。
- 円、曲線、自由描画、下絵画像は第一リリースに含めない。

## 6. 直接操作

### 6.1 通常状態

- 空白部分の左ドラッグで矩形を作成する。
- 図形内部のドラッグで、グリッドにスナップしながら移動する。
- クリックで単一選択する。
- `Shift + クリック` で選択対象を追加または解除する。
- `Shift + 空白ドラッグ` で範囲選択する。
- 選択外の空白クリックで選択を解除する。

### 6.2 変形

- 矩形は、選択中に現れる辺・角のハンドルで伸縮する。
- ポリゴンは、選択中に現れる頂点・辺を直接動かして変形する。
- ポリゴンにバウンディングボックスでの比例拡大・縮小は提供しない。
- 回転は90度単位とし、回転後も全頂点をグリッド上に保つ。

### 6.3 ポリゴン作成

- `P` または追加メニューから一時的なポリゴン作成へ入る。
- ポリゴン確定後は通常状態へ戻り、作成した図形を選択する。

## 7. 複数図形

- コピー、貼り付け、複製、削除を提供する。
- 前面へ、背面へ、最前面へ、最背面へ移動できる。
- 複数選択した図形を結合できる。結合は選択図形の論理和を取り、最前面の図形の名前とスタイルを引き継いだ一つの図形にする。重ならず辺でも接しない図形は結合できない。
- 複数選択した図形をくり抜ける。くり抜きは最前面の図形を型として、それ以外の選択図形から差を取る。型に使った図形は消え、空になった図形は削除する。
- 結合とくり抜きはそれぞれ一つのCommandとし、Undoで元の図形をすべて戻す。
- 複数選択した図形をグループ化・解除できる。
- グループは一階層だけとし、入れ子を許可しない。
- 通常はグループを一体として選択・移動・複製・削除・90度回転する。
- グループのダブルクリックで構成図形を個別選択できる。
- 第一リリースではグループ全体の拡大・縮小を提供しない。

## 8. 名前、寸法、スタイル

- 図形に任意の名前を設定でき、名前はキャンバスと共有画像へ常時表示する。
- 新しいスケッチはセル数を寸法として扱う。
- 任意で `1セル = 数値 + mm/cm/m` の実寸スケールを設定できる。
- 選択中の図形に幅と高さを表示する。
- 共有画像に寸法を含めるかを切り替えられる。
- 図形には厳選した塗り色、透明度、境界線の表示・非表示を設定できる。
- 境界線の色と太さはテーマから自動決定し、個別設定させない。
- 自由テキスト、線、矢印は第一リリースに含めない。

## 9. 保存と復元

- ユーザーが明示的に通常の `.json` ファイルへ保存・読み込みする。
- JSONには形式バージョンを持たせるが、過去のGridder JSONとの互換性は提供しない。
- Chromiumでは、初回に保存場所を選び、その後は同じファイルへ保存できる。
- FirefoxとSafariでは、必要な標準APIがない間はファイル選択とダウンロードを使う。
- 未保存の変更がある状態で新規作成、読み込み、ページ離脱を行う場合は確認する。
- 未保存内容はクラッシュ復元専用のドラフトとしてブラウザ内へ一時保持する。
- 正常終了後の通常起動ではドラフトを自動的に開かない。
- 異常終了後だけ復元するか確認する。

## 10. 画像書き出し

- 描画範囲だけをPNGまたはJPEGへ書き出す。
- 既定形式はPNG、既定背景は白とする。
- グリッドを画像へ含めるかを選択できる。
- 図形名は含め、寸法は切り替え可能とする。
- 選択枠、ハンドル、カーソル、エディタUIは含めない。

## 11. UndoとRedo

- 文書を変更する操作はすべてCommandとして記録する。
- 図形作成、移動、変形、結合、くり抜き、スタイル変更、グループ操作、描画範囲変更をUndo/Redoできる。
- ドラッグ中の連続更新は、確定時に一つのCommandへまとめる。
- ビューポートのズームとパンは履歴へ含めない。
- Undo履歴はJSONへ保存しない。

## 12. UI構成

- ファイル、Undo/Redo、ポリゴン追加、共有を置くコンパクトな上部バーを使う。
- 左側の常設ツールバーは置かない。
- 選択中だけ右側にコンテキストインスペクターを表示する。
- グローバル設定は上部バーから開く小さなパネルへ置く。
- よく使う操作はキャンバス上の直接操作とキーボードショートカットを優先する。
- UIの視覚・操作原則は `docs/ui-principles.md` に定義する。

## 13. 技術構成

- React 19、TypeScript、Vite
- Konva / react-konva。1図形を1ポリゴンとして描画する
- framework-freeなTypeScriptエディタコアを文書状態の正規ソースにする
- Zustandは選択、ビューポート、一時操作などUI状態だけに使う
- ポリゴン論理演算はpermissive OSSをAdapter越しに利用する
- Gridder独自コンポーネントの内部でheadless UI primitiveを利用する
- Tailwind CSSとLucide icons
- Vitest、React Testing Library、Playwright
- Yjs、共同編集、Rustバックエンド、PixiJSは第一リリースから削除する

## 14. 性能基準

- 基準データは最大約500図形、50,000セル相当とする。
- 基準データでパン、ズーム、移動、矩形伸縮を継続的に操作できること。
- ドラッグ中にReactの文書状態を毎フレーム更新せず、確定時に反映する。
- 性能判断は実機のフレーム時間と入力遅延を計測して行う。

## 15. プロトタイプ合格条件

次の操作を一つの画面で検証できること。

- 空白ドラッグによる矩形作成
- クリック選択、移動、辺・角による矩形伸縮
- `Shift`を使った複数選択
- カーソル中心ズームとパン
- 選択時だけ現れる右インスペクター
- 図形名、色、透明度、境界線の変更
- 描画範囲の自動設定と手動調整

プロトタイプでは保存、ポリゴン論理演算、グループ化、画像書き出しを本実装しない。
